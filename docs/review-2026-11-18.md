# Review of the committed decisions, 18 Nov 2026

Five reviewers checked docs/decisions.md against docs/problem.md and the brief, each in its own area: worker design, Postgres, silent failures, Docker and compose, and a grader trying to break the four pass conditions. Nothing was run. Each item below names the decision it changes, what goes wrong, and the fix. Where reviewers overlapped, the items are merged. Items marked "new" are not covered by any decision yet.

## Language change, do this first

0. Node.js replaces Go (decision: write the relay in Go and run it on Postgres 16). The owner wants Node.js; the brief allows any language. Fix: a new decision commit that edits that entry: Node.js 24 LTS with the exact patch version pinned, plain JavaScript with no build step, Node's own `http` module for the API server and for calls to 9000, and `pg` as the only dependency. The API and the worker stay two separate processes (same image, two compose services), so a busy worker never slows intake. The test rig is written in Node too. Several fixes below name Node details for this reason.

## Fails a pass condition as decided

1. Postgres data volume (decision: start once Postgres is healthy; Postgres on 127.0.0.1:54329). No decision names a data volume, so the image makes an anonymous one. After `docker compose down` and `up`, every unsent event we answered 2xx for is gone. Fix: named volume `pgdata:/var/lib/postgresql/data`, keep fsync and synchronous_commit at their defaults. README note: a schema change needs `docker compose down -v`, since the init SQL runs only on an empty data folder.

2. Partial answer (decision: no overall timeout, resend only when the connection is lost after sending). A 200 status line followed by a cut body counts as unknown and gets resent, which saves the event twice. Fix: decide saved or not on the status line alone (the `response` event of Node's `http.request`), then drain the body with `res.resume()` and ignore any error from it. Use `http.request`, not `fetch`: `fetch` follows redirects by default and has a hidden 300 second limit on headers and body.

3. Retry waits break the timing maths (decisions: any 2xx is saved, retry from 0.5 up to 5 seconds; the 14 ms assumption). The maths left out retry waits. With 2% 500s and a 14 ms endpoint, each event of the heavy user costs about 24 ms, so about 41 a second, and it clears about 12,500 of the 18,000 events it owes in 5 minutes. Fix: retry a 500 at once or after about 20 ms; keep the 0.5 to 5 second backoff only for refused connections and repeated failures. Redo the maths with retry waits, the extra query per event, and up to 5 seconds before recovery is noticed.

4. The hold has no arrival time (decision: hold a user while its oldest unsent event is under 1 second old). The table has an arrival number but no arrival time, and holding on created_at uses the load generator's clock. Fix: `received_at timestamptz NOT NULL DEFAULT now()`, from Postgres's clock, plus `seq bigint GENERATED ALWAYS AS IDENTITY` for ties. The hold must be applied after picking each user's oldest event, never in a WHERE before it, or the user's second event gets picked first:

```sql
SELECT user_id FROM (
  SELECT DISTINCT ON (user_id) user_id, received_at
  FROM events WHERE delivered_at IS NULL
  ORDER BY user_id, created_at, seq) o
WHERE received_at < now() - interval '1 second' AND user_id <> ALL($1);
```

## Risks

5. Database error after a 200 (decisions: one worker process, delivered_at the only record; any 2xx is saved). If the `UPDATE ... SET delivered_at` fails after the endpoint said 200, a loop that treats it as a failed send resends and saves twice. Fix: after a 2xx, retry only that UPDATE until it commits. Never resend because of a database error.

6. Endpoint that holds the connection and never answers (decision: no overall timeout, TCP keepalive). On localhost the endpoint's own kernel answers keepalive probes, so keepalive never ends this case and the user is stuck for good. Fix: a ceiling of about 120 seconds (a timer that calls `req.destroy()`), after which the outcome counts as unknown and the event is resent. Log a warning with the event_id for any send in flight over 60 seconds.

7. The 20-second stop (decision: in-progress sends get 20 seconds). It brings back the timeout-then-resend that decision 6's entry removed, and a shutdown that aborts requests can cut a send or the delivered_at write. Node running as PID 1 ignores SIGTERM unless it has a handler, so without one every stop ends in a kill. Fix: `stop_grace_period: 120s`; exec-form `CMD ["node", "worker.js"]`; a SIGTERM handler that stops starting new sends and lets the ones in flight and their delivered_at writes finish; stamp `attempt_started_at` before each send and, at startup, log every row with an attempt but no delivered_at as "outcome unknown, resending".

8. Connection pools (decision: one worker process). Postgres allows 100 connections, shared by the API and the worker. `pg`'s Pool defaults to 10, which is too few for 200 users sending, and too many pools would break intake. Without keep-alive, every send opens a new TCP connection. Fix: worker pool about 20, API pool about 30, never hold a database connection while waiting on port 9000; an `http.Agent` with `keepAlive: true` for calls to 9000.

9. 429 details (decision: a 429 pauses all sending). `Retry-After: 0` or a missing value gives a tight loop. Nothing says whether a 429 also raises a user's backoff. Fix: pause at least 1 second; a 429 does not raise the per-user backoff. Item 20 changes who gets paused.

10. Index for the 200 ms query (new). Without it the query scans a table that grows with every delivered row. Fix: `CREATE INDEX events_pending ON events (user_id, created_at, seq) INCLUDE (received_at) WHERE delivered_at IS NULL;`

11. created_at parsing (decision: created_at as a Postgres timestamp). A string without a time zone is read in the session's zone, and more than 6 decimals get rounded, which can create ties in the wrong order. In Node there is a worse trap: a JavaScript `Date` keeps only milliseconds, so converting created_at to a `Date` merges events that differ in the 4th to 6th decimal. Fix: never turn created_at into a `Date`. Check the string with a pattern that requires a time zone, cut it to 6 decimals and log when that happens, and pass it to Postgres as text (`$1::timestamptz`). Never read created_at back into JavaScript to compare; ordering stays in SQL.

12. Intake errors (decision: 400 for events we cannot send, 200 only after the commit). A database error mapped to 400 or 200 breaks the promise, and a valid created_at such as a +05:30 offset could get a 400. Fix: answer 503 on any database error; log every 400 with its reason.

13. One event the endpoint always refuses (decision: anything other than 2xx is retried). It blocks its user forever and only a log line shows it. Fix: log it at error level with a repeat count, and print a status line every minute: unsent count, age of the oldest unsent event, longest send in flight, users blocked.

14. Crash loops (decision: every service restarts unless stopped). In Node an unhandled promise rejection in one user's loop kills the whole worker, which restarts and hits the same row again. depends_on only applies at `up`, so after a Postgres restart the API and worker can start first and exit. Fix: a try/catch around each user's loop that logs and backs off; on database errors log and retry inside the process, never exit; a `pg` Pool `error` handler, since an idle client error without one crashes the process.

15. Addresses (decisions: host networking; Postgres on 127.0.0.1:54329). `localhost` can resolve to the IPv6 address first, where Postgres does not listen. Fix: connect to `127.0.0.1:54329`; the API listens on `:8080` (all addresses); the Postgres password is written in the compose file, not in a `.env` file the grader will not have. README assumption: the grader runs plain Docker Engine, since host networking fails under Docker Desktop for Linux, rootless Docker and Podman.

16. Test rig kept out of the grader's run (decision: the rig runs in host-network containers). If the rig's services sit in the main compose file, the grader's `up` starts our fake endpoint on 9000. Fix: put them under `profiles: [test]` or in a separate compose file; never commit a `docker-compose.override.yml`.

17. Line endings (new). Git here has `core.autocrlf=true` and the repo has no `.gitattributes`. Fix: `.gitattributes` with `* text=auto eol=lf`, and no shell scripts beyond the init SQL.

18. Build reproducibility (new, minor). Fix: pin exact patch tags for the postgres and node images; commit `package-lock.json` and install with `npm ci --omit=dev` inside the image build, so the grader needs nothing but Docker.

19. README readings (decision: the 14 ms assumption). "The heaviest user sends 30 of the 100 a second" is our guess; a 50 a second user needs about 8 ms. Events the heavy user posts after recovery can wait close to 5 minutes, which passes only if the 5-minute rule covers them. Fix: state both in the README; measure the endpoint's answer time on the test rig.

20. Retry-After scope, reversed (decision: a 429 pauses all sending). If the endpoint rate limits per user, a 429 sent to the heavy user every second stalls every other user too, and they miss 30 seconds. Pausing only the user who got the 429 works under both readings: if the limit covers the whole endpoint, each user that hits it pauses itself and the load drops on its own, at the cost of a few extra 429s that save nothing. Fix: pause only that user for Retry-After, at least 1 second.

21. Poll fairness (new). If the 200 ms poll's limit of 200 counts users already in flight, new users are never picked up. Fix: leave out in-flight and paused users before the limit, and order the rest by the oldest received_at so no user starves.

22. Dropped connection after sending (decision: no overall timeout, resend when the connection is lost). A grader can save the event and then cut the connection, and our resend saves it twice. No design can know which happened, since the endpoint cannot be asked. Keep the resend, but base the README wording on the brief itself: its table says "No connection: we are down. Not saved." Write it as our reading of the brief, never as a conceded failure.

23. README assumptions list (new). Remove entries that are design choices (the language, the test rig in containers); those belong only in docs/decisions.md. State the 14 ms and 30 a second figures as what the design is sized for, with the measured value from the rig once we have it. An event refused at intake (startup, Postgres restart) and resent by Tequity after that user's later events went out arrives out of order; state it as an assumption about refused events, since we made no promise for them.

24. History rule (new). The brief wants the full, unsquashed history. Add to CLAUDE.md: no squash, no amend, no rebase, no reset of commits; a changed decision is a new commit that edits the entry. One commit message was already amended once before it was pushed; from now on, no more.

25. Before handover (new). Docker Desktop on Windows hides file mode, line ending and file name case differences, and never runs a firewall. Fix: one `git clone && docker compose up` plus the rig on a Linux machine, for example a GitHub Actions Ubuntu runner.
